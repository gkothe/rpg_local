# Backend domain values and limits review

**Scope:** Full backend source at baseline `107ea96`, including the Codex/voice integration committed at that baseline. The requested Agent 10 pass covered `rpg_be_local/src/**` and directly related Python subprocess boundaries. Fixes are in the working tree and preserve published wire values and runtime behavior.

## Verified issues fixed

- **Persisted domain sets had independent declarations.** `TurnStatus`, `CharacterType`, `SourceStatus`, and `SourceKind` were defined in [options.ts](../../rpg_be_local/src/domain/options.ts:1), while [types.ts](../../rpg_be_local/src/domain/types.ts:17), [schemas.ts](../../rpg_be_local/src/domain/schemas.ts:30), and the archive validator in [library.ts](../../rpg_be_local/src/services/library.ts:29) repeated their values. Adding a status or source kind to only one copy could make the API, mutation parser, or archive importer disagree. DTO types now derive literal unions from the canonical enums; Zod validators and runtime status/source comparisons consume those enums. Archive turns retain their narrower terminal-only set through `ARCHIVE_TURN_STATUSES`.
- **Mutation operation and field sets were repeated.** `Operation.op` and `Operation.field` in `types.ts`, the discriminated schema in `schemas.ts`, and dispatch in [state.ts](../../rpg_be_local/src/domain/state.ts:7) each spelled the operation/field vocabulary. `OPERATION_KIND`, `CHARACTER_FIELD`, and `CHARACTER_MUTABLE_FIELDS` now define it once; type discriminants use `typeof` the constants so their string-literal types remain narrow.
- **Provider identifiers and effort choices drifted across adapters.** `service.ts`, `adapters.ts`, `discovery.ts`, and config parsing independently compared or listed provider names, while Codex and Claude catalog parsing repeated the generic effort allowlist. [options.ts](../../rpg_be_local/src/providers/options.ts:1) now owns provider IDs and generic effort values; service, adapter, discovery, and config validation share them. Antigravity keeps its intentionally smaller effort vocabulary in [antigravity.ts](../../rpg_be_local/src/providers/antigravity.ts:10), which excludes `xhigh`.
- **OCR and transcription language lists had separate TypeScript copies.** Settings options, the upload route, and source/audio services could accept different lists. `OCR_LANGUAGE_CODES` and `TRANSCRIPTION_LANGUAGE_CODES` in `domain/options.ts` now feed their Zod schemas, route defaults, and service validation. The Python subprocesses retain their own local validation constants so direct subprocess invocation remains guarded.
- **Provider isolation and budget values were repeated.** Antigravity’s verified version appeared in both its support check and provenance text; its advertised input budget and parser ceiling also repeated. These now use `ANTIGRAVITY_ISOLATED_VERSION` and `MAX_PROVIDER_INPUT_TOKENS`. Codex’s 8,000-token cap remains the provider-specific `CODEX_INPUT_TOKENS`; Claude’s conservative 8,000-token catalog value is named separately because those provider decisions have distinct meanings. Generic provider efforts and Antigravity efforts remain separate.
- **Campaign budgets/defaults could diverge.** `CONTEXT_DEFAULTS` and the campaign mutation/archive Zod ranges repeated gameplay, compaction, and memory thresholds. `CONTEXT_BUDGET_LIMITS` now owns each range and default, and both validators consume it.
- **Domain size limits appeared at validation and mutation boundaries.** Entity names, long text, JSON object size, memory text, turn text, source text, page count, and archive turn count now have named declarations in [limits.ts](../../rpg_be_local/src/domain/limits.ts:1) and are shared by the route, domain validator, and archive or source service that owns each rule. Source character limits and byte limits have separate names and separate values at declaration time because `.max()` counts characters while stream/download checks count UTF-8 bytes.
- **Turn state and lease literals drifted across service and SQL consumers.** Status comparisons and transitions in `context.ts`, `turns.ts`, `campaigns.ts`, `sourceLibrary.ts`, and `store.ts` now use the domain enums. Runtime SQL status predicates and the recovery status/document value are parameterized from those enums; applied migration constraints remain untouched. Repeated lease and automatic compaction thresholds are named beside turn processing.

## Version and persistence choices

The values all happen to be `1`, but they identify separate contracts: settings response, GM response schema, and archive format. `SETTINGS_CONTRACT_VERSION`, `GM_RESPONSE_SCHEMA_VERSION`, `ARCHIVE_FORMAT_ID`, and `ARCHIVE_FORMAT_VERSION` live in [versions.ts](../../rpg_be_local/src/domain/versions.ts:1); types, schema validation, settings output, and archive import/export reference their owning value. They must advance independently when their corresponding contract changes.

Applied SQL migrations were not modified. Their closed-value checks are immutable persistence fixtures, and runtime source now uses the same wire values without rewriting migration history. Public status, source-kind, character-type, and language options keep their existing values, labels, order, and defaults.

The Python scripts remain separate processes and independently validate the OCR/transcription codes in `python/extract.py` and `python/transcribe.py`. Their accepted values currently match the TypeScript contract. This review names those local sets but does not add code generation or a shared cross-language manifest; changing a language code requires updating both sides and their subprocess tests.

This was a targeted domain/provider pass. One-off protocol and platform literals, structural property names, archive wire fixture values, and provider-specific timeouts with different purposes were left at their consumers. This report does not claim that every number or string in backend source is now a constant.
