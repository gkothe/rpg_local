# Antigravity integration evidence — 2026-10-01

The user selected Antigravity for live AI testing. No Claude or Codex model generation was used. Installed `agy` 1.2.14 authenticated through its own normal subscription session; the app never reads or exports authentication material.

Workspace-local custom agent definitions were discoverable but their canary instructions were ignored in the isolated temporary workspace. A minimal request reported roughly 13,900 input tokens; schema mode could add another turn and roughly 28,000 cumulative input tokens. These probes were not accepted as evidence of safe gameplay. A temporary exact-workspace trust experiment did not resolve the issue and its setting was restored.

A unique definition under the official global agent directory was effective. `excludeDefaultComponents: true`, `inheritCustomizations: false`, empty tools/rules/skills/plugins, no MCP and no subagents produced the mandatory instruction canary at **964 input tokens**. A separate agent instructed to read a synthetic file reported **NO_TOOLS**, with **994 input tokens**, and did not return its contents. The initialization event still advertises a broad inventory: it is not proof that those tools are granted to the custom agent.

The shipped adapter creates a unique global definition for each invocation, selects it explicitly, supplies one stdin message in a fresh temporary workspace, and deletes only that definition afterward. It does not change trust, user settings, shared skills or credentials. It checks hooks before each call and refuses active hooks because the CLI preserves post-invocation hooks. CLI 1.2.14 is the verified version; other versions fail closed pending equivalent validation. No `--dangerously-skip-permissions` flag is used.

Discovery reads `agy models`, grouping **14 returned variants into seven model families** with separate effort choices. It resolves each chosen effort back to its CLI slug. Availability is not a guarantee that every listed model is entitled to the account. Real `gemini-3.8-flash-low` generation and `gemini-3.7-flash-low` memory generation passed through ProviderService. A real PostgreSQL turn then changed the Ranger's health **8 → 12** and potion count **1 → 0**; full undo restored both and preserved a private note. The immutable application context estimate was **2,751 UTF-8 bytes**. That disposable campaign was deleted after verification.

Input assembly uses conservative UTF-8 byte estimates and reserves 3,200 for the provider/system envelope separately for gameplay, compaction and draft parsing. The adapter checks its stdin envelope, verifies its own selected agent and one-turn success, and rejects reported input over 16,000. Structured output remains validated against the backend schema before state changes; this cannot prove narrative truth. Responses fenced as one JSON block are accepted; malformed, failed, multi-turn or oversized results are rejected.

Official references: [custom agents](https://www.agy.dev/docs/subagents?tab=cli), [headless protocol](https://www.agy.dev/docs/cli/headless/), and installed CLI changelog entries for `excludeDefaultComponents`/`inheritCustomizations`. Codex 0.159.2 now supports verified empty-tool isolated requests (native anonymous-loopback protocol tests, no live model claim); see codex-provider-status.md.
